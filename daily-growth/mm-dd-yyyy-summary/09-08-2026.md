# 09-08-2026 Summary

## Breadcrumbs

**Separate JavaScript and TypeScript courses**
- Reviewed the Academy loader, lesson schema, existing Rust course, UI,
  packaging, and earlier combined JS/TS roadmap with three agents.
- Followed today's decision to ship two independent courses. The earlier
  `js-ts` roadmap now points to the implemented layout and records the change
  from proposed runtime-only `tsx` checks to strict TypeScript compilation.
- JavaScript: five modules and 11 lessons covering Node setup, values and
  coercion, control flow, closures and `this`, immutable records, collection
  pipelines, errors, ES modules, promises, streams, and an expense-report CLI.
- TypeScript: five modules and 10 lessons covering compiler contracts,
  inference, unknown-data validation, exhaustive unions, interfaces and
  utility types, generics, typed async results, module refactoring, and a
  two-part ledger boundary/report project.
- Every lesson includes original explanations, visible worked examples,
  an exercise, inline starter/solution files, and deterministic assertions.
  Content lives under `assets/academy/courses/javascript` and `typescript`.

**Practice and authoring tools**
- Added `scripts/check_academy_courses.py`: each solution must pass its
  declared check, and each starter must fail, in separate temporary directories.
- Added `--export COURSE LESSON DESTINATION` to extract starter files for
  terminal practice. Export refuses existing destinations to preserve work.
- JavaScript uses Node built-ins; TypeScript compiles with strict checking
  before running emitted JavaScript. Lesson checks do not install packages.
- Added a CI course-validation job using Node 22, Python 3.13, and TypeScript
  5.9.3; release bundling depends on this job succeeding.

**App integration and documentation**
- Existing manifest discovery exposes both courses and keeps their progress
  separate. Added a native blue TS badge to Academy cards/detail and Home
  progress so TypeScript is visually distinct from JavaScript.
- Bundle validation now requires Rust, JavaScript, and TypeScript manifests.
- Updated the README, architecture map, development guide, manual smoke
  checklist, and course setup guide with the current catalog and workflow.

**Review fixes**

  objects with extra properties cannot overwrite stable record IDs.

- Removed references to a nonexistent Check button, added visible syntax
